# 📋 심층 검토 및 상세 구현 계획 (Spec Audit & Review)

> **검토 기준**: 시니어 개발자 관점의 컨벤션, 아키텍처 안정성, 성능 최적화 및 UX 향상

## 1. 사전 검토 결과 및 보완점 (Review Findings)

앞서 제안된 1차 액션 플랜을 기술적, 비즈니스적 관점에서 재검토하여 다음과 같은 보완점을 도출했습니다.

### ⚠️ [기술/성능] App.jsx 모듈화 시 발생할 수 있는 이슈
*   **문제**: `React.lazy`를 이용해 코드 스플리팅을 하면 초기 로딩은 빨라지나, 네트워크 불안정 시 청크(Chunk) 로드 실패 에러 화면이 백지로 뜰 위험이 있습니다.
*   **보완**: 지연 로딩 시 보여줄 **전역 로딩 스피너(Suspense Fallback)**와 청크 로드 실패를 우아하게 처리할 **ErrorBoundary 컴포넌트**가 필수적으로 동반되어야 합니다.

### ⚠️ [데이터/로직] '학습 이어하기' 버튼의 한계
*   **문제**: 현재 `storageManager`는 사용자가 '마지막으로 학습한 단원'이 어디인지 추적하지 않습니다. 버튼을 만들어도 갈 곳이 없습니다.
*   **보완**: `storageData` 구조에 `lastLearned: { path, title }` 필드를 추가하고, 각 단원 페이지에 진입할 때 이를 갱신하는 커스텀 훅(`useTrackProgress`)을 먼저 구현해야 합니다.

### ⚠️ [UI/UX] 메인 페이지 비대화 방지 (인지 과부하)
*   **문제**: 펫 위젯, 레벨, 뱃지, 랭킹, 부모님 도구까지 모두 한 화면에 노출하면 시선이 분산되어 혼란스러울 수 있습니다.
*   **보완**: **사용자 페르소나 분리**가 필요합니다. 상단은 철저히 '아이들' 중심(펫, 이어하기, 게임), 하단은 '학부모' 중심(학습지, 리포트)으로 섹션을 명확히 나누고, Glassmorphism(반투명 유리 효과)을 통해 시각적 계층을 분리합니다.

## 2. 상세 구현 로드맵 (Action Plan v2.0)

안정성과 성능을 보장하기 위해 다음 3단계(Phase)로 나누어 순차적으로 진행합니다.

### 🛠️ Phase 1: 기반 시스템 공사 (Data & Routing)
1.  **학습 추적 로직 추가 (`storageManager.js`)**
    *   기본 상태에 `lastLearned: null` 추가.
    *   학습 페이지 마운트 시 호출될 `useTrackProgress` 훅 생성.
2.  **라우팅 모듈화 및 최적화 (`App.jsx` 리팩터링)**
    *   `src/routes/` 폴더 생성 후 학년별 라우트(`Grade1Routes.jsx` 등) 분리.
    *   `App.jsx`에서 `React.lazy`로 학년별 라우트 지연 로딩.
    *   청크 에러 대비 `ErrorBoundary` 및 `GlobalSuspense` 적용.

### 🎨 Phase 2: 메인 페이지 컴포넌트 개발 (HomePage UI)
1.  **Hero Section (학습 관제탑)**
    *   **펫 위젯**: 현재 적용된 버프 상태에 따라 표정이 변하는 펫 아바타 노출 (3D 렌더링 부하를 피해 2D 기반으로 가볍게 구성).
    *   **이어하기 버튼**: `lastLearned` 데이터가 있으면 해당 경로로 펄스(Pulse) 애니메이션과 함께 유도.
2.  **Parent's Corner (학부모 전용 섹션)**
    *   명확히 구분된 하단 영역에 '문장제 학습지 출력', '학년별 퀴즈 생성', '학습 리포트' 바로가기 카드 배치.

### ✨ Phase 3: 비주얼 폴리싱 및 검증
1.  **디자인 시스템 적용**: Vanilla CSS와 Framer Motion을 결합하여 현대적인 Glassmorphism 카드 UI 적용.
2.  **성능 테스트**: Vite 빌드 후 Bundle Size 감소 확인 (App.jsx 비대화 해소 검증).
