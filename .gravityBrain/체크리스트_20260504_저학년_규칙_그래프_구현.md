## 1단계: 컴포넌트 구조 설계

### 구현 대상 (총 4개)

| 학년 | 단원 | 컴포넌트명 | 파일 경로 | 난이도 |
|------|------|-----------|-----------|--------|
| 1학년 | 규칙 찾기 | Patterns1st | grade1/Patterns1st.jsx | 쉬움 |
| 1학년 | 표와 그래프 | Graph1st | grade1/Graph1st.jsx | 쉬움 |
| 2학년 | 규칙 찾기 | Patterns2nd | grade2/Patterns2nd.jsx | 보통 |
| 2학년 | 표와 그래프 | Graph2nd | grade2/Graph2nd.jsx | 보통 |

### 교과과정 기준 내용

**1학년 규칙 찾기**:
- 반복되는 모양 패턴 (○△□○△□...)
- 반복되는 숫자 패턴 (1,2,3,1,2,3...)
- 색상 패턴 (빨노초빨노초...)
- 간단한 규칙 예측

**1학년 표와 그래프**:
- 좋아하는 동물/색깔/과일 조사
- 간단한 표 완성하기
- 막대그래프 그리기
- 가장 많은 것/적은 것 찾기

**2학년 규칙 찾기**:
- 1학년 내용 심화
- 덧셈/뺄셈 패턴 (2,4,6,8...)
- 도형 패턴 심화
- 다음에 올 것 예측

**2학년 표와 그래프**:
- 1학년 내용 심화
- 표에서 정보 읽기
- 막대그래프 해석
- 간단한 데이터 비교

## 2단계: 구현 계획

### 공통 구조 (모든 컴포넌트)

```jsx
- PageHeader (단원 제목)
- 개념 설명 섹션
- 인터랙티브 활동 (2~3개)
- 퀴즈/게임 요소
- 보상 시스템 연동 (XP/코인)
```

### MASC 분석

**PM 관점**:
- 1학년은 매우 쉬운 개념만 (시각적 패턴 위주)
- 2학년은 약간의 계산 포함 (덧셈 패턴 등)
- 기존 3학년 컴포넌트와 비슷한 난이도 분위기 유지

**아키텍트 관점**:
- 기존 grade1, grade2 컴포넌트들과 동일한 패턴 사용
- storageManager 연동 (updateCoins, addXP)
- 재사용 가능한 패턴 로직은 분리 고려

**보안 관점**:
- 클리언트 사이드 계산만 있으므로 보안 리스크 없음
- 기존 컴포넌트와 동일한 보안 수준
